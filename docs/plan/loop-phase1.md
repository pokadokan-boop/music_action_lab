# 回す仕組み 計画 Phase 1: 引き継ぎファイル (段階 1)
作成 2026-10-27。承認済み 2026-10-27 (同日実装)。根拠となる詰まり: 2026-10-22〜27 の 4 日で v0 → v1 を 5 周回したが、毎回「セッションを切る」「次の指示を打つ」「計画を承認する」を本人が手でやった。本人は「毎回自分の手で切ったり指示したりしたくない」(system-design「仕組みの変更には実際に回して出た詰まりを根拠として紐づける」に従い、ここで仕組みを 1 段足す)。

## 目的
本人がやることを「`claude` を開く」「遊ぶ」「不満を書く」の 3 つに減らす。セッションの切り方と次の指示は Claude 側で決める。

## 段階 1 の完了条件
- `docs/NEXT.md` があり、「次の 1 手」「今の状態」「本人に聞きたいこと」の 3 節で書かれている
- プロジェクトの CLAUDE.md に、セッション開始時の手順 (NEXT.md を読む → 本人の指示を待たずに始める) と、セッションの終わり方 (NEXT.md を書いて commit → 止まる) が書かれている
- 2 セッション続けて、本人が `claude` を開く以外の指示を打たずに作業が始まり、終わりで NEXT.md が更新されている

## 2026-10-29 の変更: 「切ってください」の廃止
- 詰まり: 本人が「細かく切るのはただ手間が増えているだけ。自分とのやり取りが含まれる時点で無理か」。同日のセッションで、本人の返事 (push の認証、v3 Phase 1 への返事) の途中に Claude が「切ってください」を 2 回挟んだ
- 読み: 切る理由は文脈の大きさ (要約で情報が落ちる) であって、本人とのやり取りではない。区切りの実体は NEXT.md と計画文書を最新にすることで、それは切らなくてもできる。当初の「切ってください」は、切る判断を本人から Claude に移したつもりで、切る作業を本人に残していた
- 変更: CLAUDE.md「セッションの終わり方」を「区切りの作り方」に。Claude は区切りごとに commit → NEXT.md → push までを行いそのまま続ける。止まるのは本人の確認待ちだけ。要約の後は NEXT.md と計画文書を読み直す。やり取りの途中で区切りの手順を挟まない
