# 回す仕組み 計画 Phase 1: 引き継ぎファイル (段階 1)
作成 2026-10-27。承認済み 2026-10-27 (T1〜T3 は同日実装)。根拠となる詰まり: 2026-10-22〜27 の 4 日で v0 → v1 を 5 周回したが、毎回「セッションを切る」「次の指示を打つ」「計画を承認する」を本人が手でやった。本人は「毎回自分の手で切ったり指示したりしたくない」(system-design「仕組みの変更には実際に回して出た詰まりを根拠として紐づける」に従い、ここで仕組みを 1 段足す)。

音楽の作業から離れない。この計画は 1 セッションの前半で終え、同じセッションの後半で v2 (docs/plan/v2-phase1.md) に入る。

## 目的
本人がやることを「`claude` を開く」「遊ぶ」「不満を書く」「キューの範囲を合意する」の 4 つに減らす。セッションの切り方と次の指示は Claude 側で決める。

## 段階 1 の完了条件
- `docs/NEXT.md` があり、「次の 1 手」「今の状態」「本人に聞きたいこと」の 3 節で書かれている
- プロジェクトの CLAUDE.md に、セッション開始時の手順 (NEXT.md を読む → 本人の指示を待たずに始める) と、セッションの終わり方 (NEXT.md を書いて commit → 止まる) が書かれている
- 2 セッション続けて、本人が `claude` を開く以外の指示を打たずに作業が始まり、終わりで NEXT.md が更新されている

## 段階 2 (無人の実行) の概要。この計画の範囲外
- `claude -p` をキューの 1 項目ずつ起動する小さなスクリプト (キュー = `docs/queue.md`、1 項目 = 1 セッション)。毎回新しいセッションなので文脈の肥大と「切る」が消える。Windows のタスクスケジューラで本人が家にいない時間に回す
- 承認はキュー単位 (キューの範囲を 1 回合意したら各項目は承認なしで進む)。判断が要る項目は vault のノートに質問を書いて止まる
- 実行の先頭で vault の不満ノートを見て、新しい不満があればそれを次の版に落とし、なければキューの続きをやる
- with-codex の自律バッチと同じ考え方だが、plugin は入れず、キューのファイルと起動スクリプト 1 本をここに書く
- 着手の条件: 段階 1 で 2〜3 セッション回して「開くだけでも面倒」と感じたとき

## タスク
### T1 (NEXT.md の形式と初版) [仕組み]
- `docs/NEXT.md` を作る。3 節:
  - 「次の 1 手」: 次のセッションが最初にやる作業を、読む文書と終了条件つきで 5 行以内
  - 「今の状態」: 公開 URL、最新 commit の要旨、テスト件数、未 push の有無
  - 「本人に聞きたいこと」: 無ければ「なし」。あれば番号つきで、答えが無くても進められる範囲を添える
- 初版の「次の 1 手」は v2 の T1 (立ち上がり時刻の測定の道具) にする。ただし v2 は Phase 1 未承認なので「承認を取ってから」と書く

### T2 (CLAUDE.md のセッション規律) [仕組み]
- 「セッションの始め方」節: docs/NEXT.md を読み、「次の 1 手」から始める。本人の指示を待たない。本人が別の指示を出したらそちらを優先する
- 「セッションの終わり方」節: 区切りのよい commit を作り、NEXT.md を書き直して commit・push し、「切ってください」と一言で止まる。終わる判断の目安: (a) 計画のタスクが 1 つ終わった、(b) 本人の確認待ちになった、(c) 文脈が重くなった (目安は本人に聞かず Claude が判断。長い作業の途中で切らない)
- 「承認の扱い」節: 本人の global CLAUDE.md の Phase 1 / Phase 2 承認は残す。ただし承認済みの計画の範囲内なら、セッションをまたいでも再承認は求めない (計画文書に「承認済み」と日付を書く)

### T3 (今回の分の移行) [仕組み]
- v2 の計画文書の「新しいセッションの始め方」を NEXT.md 側に寄せ、計画文書からは参照だけにする (二重に書かない)
- README「次のセッションの手順」を NEXT.md への参照にする
- 本人への最後の案内は「次は `claude` を開くだけでよい」の 1 行にする

## 人間の作業
1. この計画の承認 (次のセッションの冒頭。承認されたら T1〜T3 をそのまま実装し、同じセッションで v2 の Phase 1 承認に進む)
2. 2 セッションぶん、`claude` を開くだけで始まるかを見る

## 決めていないこと
- 「文脈が重くなった」の目安: 作業量で代える案 (大きなタスク 1 つ、または commit 3 つ) を CLAUDE.md に採用した (2026-10-27)。回して合わなければ直す
- 段階 2 で、スマホから実行を起こす手段 (Claude Code remote control から `claude -p` を呼ぶか、タスクスケジューラの定時だけにするか)
