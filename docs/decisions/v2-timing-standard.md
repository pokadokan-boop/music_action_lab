# v2: 当たりの時刻の基準の検証 (2026-10-27)
docs/plan/v2-phase1.md「基準の仮説」と docs/plan/v2-phase2.md T1・T2 の記録。測定は `measure.html` (OfflineAudioContext で src/audio/engine.ts をそのまま描画) を Chrome で開き、`window.__measure` を読んだ。判定の規則は測る前に v2-phase2.md T2 に固定してある。

## 結論
仮説は外れた。2 つの読み (広帯域のエネルギー、200 Hz 以下の低域) のどちらでも、叩きつけの拍の立ち上がりは突進・レーザーの拍より速いか同程度で、本人の判定 (叩きつけ 80 ms、突進とレーザー 0 ms) を音の性質から説明できない。仮説は捨て、impactDelay は本人の判定値を据え置く。acceptance.json への検査の追加 (`impact-rise`) はしない。

## 測定の設定
- RMS 窓 10 ms (時刻 t で終わる後ろ向きの窓)、刻み 1 ms
- 基準 = [t0 − 30 ms, t0 − 5 ms] の平均、ピーク = [t0, t0 + 150 ms] の最大。立ち上がり = 基準 + 90% × (ピーク − 基準) に初めて達する時刻 − t0。50% も併記
- 低域 = 200 Hz の 2 次バイカッド (Butterworth) ローパス後に同じ計算
- t0 = hitBeat × 1 拍の秒数 (140 BPM、1 拍 428.6 ms)。合成は 48 kHz、モノラル
- 偏り: 後ろ向き窓のため真の値より系統的に遅く出る (5 ms ランプで約 +7 ms、ステップで約 +9 ms。src/audio/onset.test.ts で確認)。低域はさらにローパスの群遅延 約 1 ms。下の表は補正前の生の値

## なぜ外れたか (測る前に書いた読みの確認)
v2-phase2.md T1「先に書いておく読み」のとおり、engine.ts のキックは音量 0.6 から始まって指数減衰する形で、立ち上がりのランプが無い。メロディ (5 ms ランプ) と合わさって、叩きつけの拍はむしろ最も速く立ち上がる。低域についても、150 → 40 Hz の掃引の最初の 1 周期 (約 7 ms) で RMS がほぼピークに達するため、「沈むにつれて低域が増える」という第 2 の読みは RMS の指標では現れなかった。

## 捨てたもの、残すもの
- 捨てる: 「当たりが合って感じる時刻 = 合成波形のエネルギーが立ち上がりきる時刻」。この合成器では音の種類による差が 10 ms 以下で、80 ms の差を作れない
- 残す: 道具 (measure.html、src/audio/onset.ts)。合成器や曲を変えたときに、同じ指標で差を見られる
- 据え置く: a2 (→ v2.json) の impactDelayBeats 0.1875 (80 ms) と、突進・レーザーの 0 ms。根拠は本人の判定のみ (docs/decisions/v1-feedback.md 不満 3 と、vault の v1 の判定)。基準は「無し」のまま

## 次の仮説の候補 (採用しない。記録のみ。本人の判定を材料にして基準を作らない原則は守る)
1. 音ではなく絵の側。叩きつけは「動き出し → 着地」の縦の移動 (0.25 の距離) を見せる攻撃で、動きが動きとして読めるのに最低限の時間が要る。突進は本体が音のなり始めに動き出して届くのが少し後、レーザーは瞬間に出る。80 ms は「動きを見せてから当てる」ための時間で、音の性質ではない可能性。検証するなら、叩きつけの移動距離を変えて (0.1 と 0.4)、合って感じる遅れが距離に比例するかを見る
2. 低い音の知覚の遅れ。RMS は 1 周期で立つが、40〜150 Hz の音が「音として」聞こえるには数周期かかる。RMS ではなく聴覚モデル (ラウドネスの時間積分) で測る必要がある。この合成器のキックに限った話なので、優先度は 1 より低い
3. 出力機材の低域の再現。ヘッドホンやスピーカーで 40〜150 Hz が弱いと、キックの知覚上の立ち上がりが変わる。ソフトだけでは測れない (docs/research/av-sync-verification.md)
