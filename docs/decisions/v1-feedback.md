# v1 の不満の分解 (2026-10-22)
出典: 本人の会話での発言 (A' を遊んだ直後)。vault の不満ノートには書かれていない。

## 不満 → 変更
| # | 不満 (要約) | 原因の読み | 変更 |
|---|---|---|---|
| 1 | 曲側の音のタイミングと動きのタイミングが合っていない。キビキビさは要るが、それ以前の問題 | 範囲攻撃 (Z のフレーズ) のキーフレームが音の位置に無かった。最初の音 (8 拍目) からゆっくり降り続け、当たりは音の無い休み小節のキック (12 拍目) にあった。snap で加速させても「無音の間に動いている」ことは変わらない | 本人の案どおり: 最初の音で最終地点の少し上まで動く (8→8.25)、無音は止まる (8.25→10.25)、最後の音 (10.5) で叩きつけて当たりを出す。戻りは休み小節の頭のキック (12→12.5)。a2 の phrase 2/5/8 に適用 |
| 2 | 突進と射撃は移動と音のタイミングが合っている | dash は 18 拍目の音で突進、laser は 4.5 の音で沈み 6 の音で撃つ。キーフレームが音の位置にある | 変更なし |
| 3 | (直した後) 最後の音の前に動き出してしまう。他が合って見えるのは、なり始めではなく少し後ろに合っているからでは。アタックが立ち上がりきる瞬間に判定が出るとよい | 叩きつけを「音の 0.25 拍前に動き始めて音と同時に着地」にしていた。dash は本体が音と同時に動き出し、当たりは本体が届いた少し後なので、結果的に「立ち上がりの少し後」に当たっていた。加えて、ブラウザの音の出力遅延ぶん絵が音より先行していた | `impactDelayBeats` を足し、動き出しを音のなり始め (10.5)、着地と判定を 1/8 拍後 (10.625) にした。検査は hitBeat (音のアンカー) で見る。ゲーム時計を AudioContext の outputLatency ぶん遅らせ、絵と判定を聞こえる音に合わせた (結果画面に補正値を出す) |

## 仕組みの変更
- burst の発生位置を「path の最後の点」から「当たり拍の時点の位置」に変えた。叩きつけた後に戻る動きを path に書けるようにするため
- docs/choreo-format.md に「書き方の指針」を足した: キーフレームは音の位置に置く / 無音は止まる / 当たりは最後の音に置く / 戻りも音に合わせる。機械検査にはしていない (キーフレームが音や拍に乗っているかの検査は候補として残す)

## 学び
- v0 の不満 1「拍ごとの動きの量が変わらない」は、補間の形 (easeOut か snap か) の問題ではなく、キーフレームが音に乗っていない問題だった。snap はキビキビさとして残すが、主因ではない
- 2 案比較で A' を出したことで、本人が「突進と射撃は合っている」と切り分けられた。合っている攻撃と合っていない攻撃の差 (キーフレームが音にあるか) が原因の特定に効いた
