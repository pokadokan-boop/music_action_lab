# 音楽とゲームの実現可能性
vault:with-codexの後継-人間を不満の源泉にする自律システム.md から移したもの (2026-10-20)。

## 調べた動機 (この対話での発言)
- 一番楽しいと思うのは音楽とゲーム (2D アクションを想像しているが、それ以外でもよい)
- 技術的に行けそうなのはちょい単発系 (餃子型のボケ、vault:単発/ブラウザ上SCP.md の不条理、ヒステリック陰謀論。アプリのつなぎ込みは要る)
- 作曲能力には頼れない。mid はフレーズもできていない。人間の役割は手触りを伝えるだけになりそう

## 調査結果 (サブエージェントのウェブ調査、2026-10-20)
音楽とゲームを 2 体で並列に調べた。出典は報告に載っていたもので、Claude は原文を開いていない。

ゲーム
- 一番自律化しやすいのはブラウザ製 (TypeScript + Canvas + Web Audio) を Playwright で自動プレイする形。ゲームに `advanceTime(ms)` (時間を固定ステップで進める) と `render_game_to_text()` (状態をテキストで出す) を持たせる定番がある (OpenAI の develop-web-game スキル、Claude Code 向けの opusgamelabs/game-creator)
- MIDI は `@tonejs/midi` で JSON にでき、「MIDI → 敵の行動タイムライン」を描画から切り離してテストできる
- GitHub Pages や itch.io (Mobile Friendly) に置けばスマホで遊べる。反応は Claude Code の Remote Control でスクショと一言を送れる
- Godot なら satelliteoflove/godot-mcp が入力注入とゲーム時間のコマ送りを持つ (Godot 4.5 以上)。Web 版の音ズレと重さは未測定
- 自律化できないのは手触りと面白さ (「テストで分かるのは動くかどうかで、手触りではない」という報告)。VLM に画面を見て遊ばせる方式はほぼランダムな性能 (lmgame-Bench、VideoGameBench)
- スマホブラウザの音ズレは端末ごとに違い、実機でのキャリブレーションが要る (Rhythm Quest の devlog)
- エージェントが書いたテストは自分のコードに合わせてしまう。合否条件はエージェントが編集できない場所に固定する

音楽
- 音声生成サービス (Lyria、ElevenLabs Music、Suno、ACE-Step 等) はどれも MIDI を出さず、ゲームとの同期には合わない。Suno は一般公開の API が無い
- MIDI を直接出すモデル: MIDI-LLM (VRAM 16GB 以上推奨)、text2midi (MIT、品質は弱め)、Anticipatory Music Transformer (Apache 2.0、一部を固定して残りを埋める)
- LLM 単体の作曲は弱い (ComposerX の著者報告、ABC-Eval)。music21 を道具に持たせると改善する (CSyMR-Bench)。外部の統計で判定して直す先行例に Libretto (arXiv 2606.22708)
- 判定ツール: music21 (調推定)、MusPy (音高のエントロピー等)、pretty_midi / mido で拍・密度・音域を自作チェック。音声側は Beat This! (拍検出)、Basic Pitch (音声 → MIDI)
- 鼻歌 → MIDI の経路もある (Basic Pitch、スマホアプリ)。誤差は乗る
- ゲーム内で鳴らすなら Tone.js (MIT) か WebAudio。Strudel は AGPL なのでゲームには埋め込まない

## 実現可能性のフック (Claude の整理、未検証)
- 自律化できない部分 (手触り・面白さ) が、人間の役割 (出発点の要望と不満の源泉) にそのまま重なる
- MIDI を正本にすると、曲・敵の行動・判定が同じデータでつながり、機械で検査できる
- 時間を自分で進められる作りにすると、拍との同期を毎回同じ結果で検査できる
- 合否条件は数値にして、エージェントが変えられない場所に置く
- 曲の条件は作曲せず言葉で出せる。vault:音楽アクション/音楽参考.md の「4 拍子で 8 連打じゃなく 4 音」「構成要素が少ない」は、ノート密度とトラック数として機械判定できる。ただし 2026-10-21 に「探すときの目安であり必須条件ではない」と決め、合否条件には置かない (docs/concept.md「曲」)
- 曲を自分のフレーズから作らない場合は、AI が候補を複数出し、自分は選んで理由を一言返す。選ぶのは作曲ではなく反応
- 最初の題材の候補は vault:音楽アクション/1つ曲に対して複数のアクションを作る.md の「20 秒のフレーズで戦闘シーンも曲も作る」。20 秒・敵 1 体・曲 1 つの枠を先に固定しないと、仕組みの方が育つ

## 残る穴
- 曲の個性。自分のフレーズが無いと、個性は選択と不満からしか入らない。それで足りるかは分からない (感性システムの問題そのもの)
- 手触りの言語化。自由記述でなく、2 案の比較とゲーム内の記録 (入力と拍のズレ、被弾タイミング) で補う案がある (Claude の提案)
- スマホブラウザでの音ズレの実測 (2026-10-21: 遊ぶ側は PC ブラウザ + DualSense に決まり、スマホは反応を返す側になったため優先度は下がった。docs/concept.md「範囲」)
