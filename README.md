# music_action_lab
音楽アクションの最初の実験。20 秒の戦闘シーン (敵 1 体、曲 1 つ) を、遊んだ人間の不満だけを源泉にして育てる。

## 遊ぶ (v6)
- URL: https://pokadokan-boop.github.io/music_action_lab/
- PC のブラウザで開く。DualSense を USB か Bluetooth でつなぎ、ボタンを 1 回押すと認識される。キーボードでも遊べる
- 操作 (v6 で左手を足した): 左スティック (WASD / 矢印) で移動、R1 (Space / J) で右手の攻撃、L1 (F) で左手の攻撃、○ (K) でステップ。× はタイトルと結果画面の決定だけ。常に浮いていて重力は無い。右手と左手はそれぞれ独立に通常攻撃・溜め・放ちを持つ (片手で溜めながらもう片手で捌ける)。両手の放ちを 16 分 (0.25 拍) 以内に重ねると「両手放ち」として記録される
- 行動 (v5。docs/plan/v5-phase1.md): 押した瞬間に通常攻撃。押し続けて 0.5 拍を超えると溜め (持続音が上がる。動けてステップもできる。被弾で解除)。離した瞬間に放つ (ダメージ 3、長い音)。放ちで相殺が成立すると「強い相殺」で敵にダメージ 3。相殺の直後 1 拍の攻撃は「返し」(短く高い音。スティックを倒していれば踏み込む。v6.1: 敵が扇の向きにいれば敵へ向かって接触する距離まで (最大 0.1。通り過ぎない)、いなければスティックの向きへ 0.1)。ステップは 0.5 拍の短いダッシュ (無敵なし、短い打音。2 連で「タタンッ」)
- 自分の音の音高はタイトルで 3 案から選べる (案 1 コードの音 / 案 2 メロディをなぞる / 案 3 固定 = v3 の値)。選んだ案は結果の要約の先頭行に出る。音楽として良いかは本人が聴いて決める
- 自分の音の音色 (v6) は音作りのページ https://pokadokan-boop.github.io/music_action_lab/sound.html で作れる (行動ごとに最大 4 層、鳴らす・曲の 1 小節と重ねる・波形を描く・JSON の出し入れ)。「この音をゲームに使う」で保存するとゲームが次の開始から使い、要約の先頭行に「音色 自作」と出る。作った JSON を不満ノートに貼れば次の公開版の既定になる (docs/sound-format.md)
- 音の遅れ (v6 で分かったこと): 曲と敵の絵と判定は音の出力遅延ぶん遅らせて揃えてあるが、自分の音だけは押した瞬間に予約されるので、Bluetooth イヤホン (200〜300 ms) では自分の音が遅れて聞こえる (ステップの音が終わってから鳴るように感じる)。有線か、イヤホンのゲームモード (低遅延) で遊ぶ。要約の先頭行の「音の出力遅延の補正」がその環境の遅れ (有線なら 40 ms 前後)
- 攻撃の向きはスティック (WASD) の向き。無入力なら敵の方向。当たるのは前方の扇 (見えている扇がそのまま判定) の中だけ。v6.1 から、敵の体が扇に触れていれば当たる (v6 までは敵の中心が扇に入る必要があり、扇が敵に被って見えても外れることがあった)
- 敵の突進・レーザー・叩きつけは、すべて予告開始時の自機の位置を狙う (追尾はしない)。立ち止まっていると当たる
- 敵の攻撃が自機に触れる瞬間の前 150 ms〜後 100 ms (v6.1。v6 までは前 100 / 後 50) に、来る方向へ向けて攻撃すると相殺できる。触れた後でも 100 ms 以内なら被弾が取り消される。予告が黄の攻撃 (突進・弾・レーザー) は相殺できる。紫の大技 (飛び上がって叩きつけ + 円を囲む 4 辺の極太レーザー。v6) は両手の放ちを 16 分以内に重ねたときだけ相殺でき、ジャストなほど敵へのダメージ (最大 6) と敵の反動が大きい。片手の放ちは被ダメ (2) と吹っ飛びを 2 割減らすだけ。逃げ場は円の外かつ枠の内側の帯か、撃たれる前に枠の外
- タイトルの「調整」で相殺の窓・自機と敵の大きさ・扇の半径・向きの許容角を動かせる。選んだ値は結果の要約の先頭行に出るので、不満ノートに貼れば次の版の既定値に反映される
- v4 で入ったもの: 自機は人型、敵は雫形で、構え (立つ・攻撃・相殺・被弾・構える / 攻撃の型ごと・止まっている) が変わる。突進を捌けた (相殺した、または当たらなかった) ときだけ、敵は通り過ぎた所で 1 拍止まる。これは「結果で分岐する動き」の部品を 1 箇所試したもので、一連の流れの設計は次の版 (docs/plan/v4-phase1.md)
- 振り付けは v6 の 1 本 (曲のメロディの全ての音に攻撃か大技の予告の始まり。14 攻撃。assets/choreo/README.md)。予告は型ごとに形が違う (突進は当たりのある区間だけの道と残像、弾は点線と発射点の輪、レーザーは当たりの太さの帯、大技は 4 隅へ飛ぶ発射装置と枠)。「はじめる」はクリックか Enter (ブラウザの制約で、最初の音の有効化にはクリックかキーが要る)
- 20 秒で終わり、結果画面に記録の要約が出る。「コピー」して不満ノートに貼る。v6 の要約には命中の内訳 (通常 / 返し / 放ち / 両手放ち)、行動ごとの回数と右手・左手の内訳、溜めの回数、大技の行 (片手軽減 / 両手相殺 / ジャスト率)、小節ごとの「プレイヤーの譜」(1 小節 3 行: 右手・左手・足。16 分 1 マス) が入る
- 曲候補を聴く: https://pokadokan-boop.github.io/music_action_lab/candidates.html (v7: 2 曲目の候補 4〜6 を像・大技・起伏の形つきで。1 つ選んで番号と理由を一言。docs/decisions/song-choice.md「2 曲目の候補」)
- シーン (v7): 振り付け 1 本 = 曲 1 つ + 敵 1 体 + 長さ + 敵 HP。タイトルで選べ、選択は保存される (既定は最新 = 2 曲目)。1 曲目 (v6.json) は 20 秒・敵 HP 12 のまま
- 2 曲目 (v7。candidate-4、160 BPM、36 秒、敵 HP 40。assets/choreo/README.md): 剣を持つ決闘者。大技は「三連突きからの大上段」(各段の最後の小節。短い音の数だけ突き → 長い音で紫の大上段。大上段は v6 の大技と同じく両手放ちだけで相殺、片手の放ちは軽減)。通常攻撃はその部品: 突き (短いレーザー。連撃の 2 発目以降は当たりの 1 拍前に自機を狙い直すので、歩いているだけでは当たる)、振り下ろし (長めのレーザー)、踏み込み突き (突進)、薙ぎ払い (段 2 から。回る線)、飛ぶ剣 (段 3 だけ。弾)。曲は 8 小節ごとに激しくなり、攻撃も単発 → 3 連 → 4 連と増える

## 不満を書く
vault の `音楽アクション/<版> 不満.md` (v6 なら `v6 不満.md`) に書く。1 回の不満につき 4 行以内: 版 / 何が / いつ (phrase 番号か場面) / どう嫌か。好きだった点は `+` を頭に付けて任意で。自由記述でも分解できる (docs/decisions/v2-feedback.md)。

## 次のセッションの手順
- 次は `claude` を開くだけでよい。Claude が docs/NEXT.md の「次の 1 手」から始める (規律は CLAUDE.md「セッションの始め方」「区切りの作り方」)
- 不満から次の版を作る一般の手順:
  1. docs/concept.md (保護対象) を読む
  2. vault の不満ノートと、貼られた結果の要約を読む
  3. 不満を具体的な変更に落とす。変更が concept.md の保護対象を侵すなら棄却する
  4. 2 案比較: 不満が指す軸を 1 つだけ変えた版と、直す前を並べて遊べるようにする (振り付けはデータなので、ファイルを足せば選択肢が増える)
  5. commit の先頭に `[作品]` (このゲームに属するもの: 曲・振り付け・config・ゲームのコードと文書) か `[仕組み]` (開発の流れ: NEXT.md・セッション規律・不満の受け口・hook など) を付ける (docs/decisions/commit-labels.md)

## 開発
```
npm install
npm run dev              # ローカルで遊ぶ
npm test                 # Vitest (拍グリッド、振り付けの検査、決定性)
npm run build            # 型チェック + ビルド
npm run gen:candidates   # 曲候補の再生成
npx tsx scripts/print-grid.ts assets/midi/candidate-2.mid        # 拍グリッドとフレーズ一覧
npx tsx scripts/validate-choreo.ts assets/choreo/v7.json         # 振り付けの検査 (自機狙い・等方座標・分岐・連なる攻撃・大技・連撃の狙い直し・踏み込みの検査を含む。v6.json も同じ)
npm run gen:choreo-v7                                            # 2 曲目の振り付け v7.json を小節の型から生成し直す (scripts/gen-choreo-v7.ts)
npx tsx scripts/sync-report.ts assets/choreo/v6.json             # 音と動き・当たりのずれを ms で見る
npm run dev → http://localhost:5173/music_action_lab/sound.html  # 音作りのページ (docs/sound-format.md)
node scripts/steward/collect.js                                  # 判断者が使うデータ (JSON) を見る
node scripts/steward/run.js --force                              # 無人の判断者を今すぐ走らせる (docs/plan/loop-phase2.md)
node scripts/steward/register.js query                           # Task Scheduler の登録状態 (create / delete / run もある)
```
- 合否条件は `acceptance.json`。Claude Code の hook が Edit/Write を止める (docs/decisions/acceptance-guard.md)
- 振り付けの形式: docs/choreo-format.md。v5 の狙い: assets/choreo/README.md。理想の動作イメージ (本人が直す叩き台): docs/play-image.md
- 設計と計画: docs/system-design.md、docs/plan/
- push すると GitHub Actions が Pages に配置する
